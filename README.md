# Codex 切换账户后项目消失、分类丢失怎么办？（2026-11-10）

**Codex Account Project Sync** 是 Windows 本地项目分类的手动备份与同步工具。针对“换号后项目不见了、不再按项目分组，但换回原账户又出现”的情况：如果本地配置仍保存着这些项目，可以让使用者选择账户、核对项目数量，再将所选账户的分类合并保留。

问题记录日期：**2026-11-10**。首版为 **v0.1.0-beta.1**，面向 Windows 11 x64；适配依据为 Codex 26.1103 系列观察到的本地账户分区与分页历史结构。结构未知时停止写入。非 OpenAI 官方工具。

[下载 Windows EXE 与源码](https://github.com/pancake-github/codex-account-project-sync/releases) · [English](README.en.md) · [验证范围](docs/validation.md) · [反馈问题](https://github.com/pancake-github/codex-account-project-sync/issues)

## 能得到什么结果

- 自动发现当前 Windows 用户所选 Codex 数据目录内已经保存的账户，不固定账户数、用户名或项目数。
- 显示账户短标识，可填写本机别名；选择一个源账户和多个目标账户，先看各账户项目数、归属数及预计变更。
- 所选账户合并保留本地项目、名称、顺序、会话归属及内部项目映射。源账户也补入目标独有的项目。
- 同标识冲突默认采用源账户并展示；源缺失、目标之间有冲突时，需要逐项选择。未选账户保持原样。
- 每次修改前备份分类配置；首次另备份受支持的本地会话数据库。提供恢复最近同步前分类的入口。

这个结果是**保留仍存在的本地分类和归属**。已删除的聊天内容、尚未在本机登录的账户和 ChatGPT 云端项目需要分别处理；项目归属记录数也不等同于现存聊天正文数。

## 普通用户怎么用

1. 等当前任务完成，正常**完全退出 Codex**。
2. 下载 Release 中的 Windows 包，解压后双击 `CodexAccountProjectSync.exe`，点击“检查账户”。EXE 自带运行时，无需安装 Python。
3. 辨认账户，可修改本机别名；选一个源账户并勾选目标。点击“生成合并预览”，核对数量、项目变更并处理冲突。
4. 点击“确认账户与数量后同步”，核对最终确认框。首次数据库备份可能较大，请等待窗口显示完成。
5. 正常打开 Codex，登录或切换到目标账户，检查项目分组与已有会话。

以后切换这些账户前，按需要手动运行一次。工具关闭后不常驻后台，也不会添加开机启动或自动切换登录。

仅关闭窗口可能仍有相关进程。工具检测到 `ChatGPT.exe`、`codex.exe` 或 `codex-code-mode-host.exe` 时会拒绝实际写入，不会强制结束它们。运行中可进行只读检查和预览。

## 数据目录、备份与恢复

默认采用当前用户的 `CODEX_HOME`；未设置时使用用户主目录下的 `.codex`。界面也可选择自定义目录。

别名、备份和回执保存在 `%LOCALAPPDATA%\CodexAccountProjectSync\profiles\` 下，按所选 Codex 数据目录分开。具体路径和首次备份大小会在确认前显示。

实际改写仅限 `.codex-global-state.json` 及其 `.bak`。不读取登录令牌文件，不改写聊天正文数据库、项目工作文件或官方程序。整个同步流程不需要联网。

首次数据库备份使用 SQLite 备份接口，包含 WAL 中已提交的数据；备份经过完整性及 SHA-256 检查。遇到未知结构、失效内部映射、空间不足、未解决冲突或确认后配置变化时，停止提交。

恢复时先完全退出 Codex，再点击“恢复上次同步前配置”。恢复前也会备份当前分类。该入口恢复分类配置，不覆盖之后新增的聊天正文和工作文件。

恢复会把两个配置文件整体还原到备份时刻，因此之后调整的分类和界面偏好也会回退；确认框会明确显示这一影响。

## 常见问题与搜索词

### Codex 切换账号项目不见了，是文件被删除了吗？

不一定。该现象可能来自账户分别保存的项目清单和会话归属。工具会检查本机已有分区；没有找到对应记录时，不会伪造恢复结果。

### Codex 项目不分组，只改“按项目显示”够吗？

如果分组设置已经开启，但当前账户缺少项目清单或会话归属，仍需核对这些记录。本工具会预览并同步所选账户的本地分类。

### 本地聊天记录与项目归属有什么区别？

聊天正文保存工作内容，归属记录决定它放在哪个项目里。工具只改分类，并核对关联会话是否仍有历史内容。没有元数据的历史归属会保留，但不会被称为已恢复对话。

### 为什么看不到邮箱？能识别不同人的账户吗？

工具识别本机配置中已存在的账户分区，用短标识和使用者填写的别名区分。它不根据摘要猜测自然人身份，不读取令牌取得邮箱，也不会扫描其他 Windows 用户。请本人辨认并确认所选账户。

### 新账户还没登录过，能提前恢复吗？

先在本机 Codex 登录一次该账户，正常退出，再检查账户。工具不会生成不存在的登录凭据或账户分区。

## 从源码运行

需要带 Tkinter 的 Python 3.10 或更高版本；运行代码仅使用标准库。

```powershell
$env:PYTHONPATH = "$PWD\src" # 从仓库源码目录加载工具模块。
python launcher.py # 打开图形界面；选择账户和预览后才可确认写入。
```

```powershell
$env:PYTHONPATH = "$PWD\src" # 让测试加载当前仓库源码。
python -m unittest discover -s tests -v # 仅测试合成配置和临时数据库。
python scripts/audit_public_tree.py # 检查待发布文件与提交历史。
```

Windows EXE 在 GitHub Actions 的独立环境构建。源码、测试、构建规则、验证边界和 MIT 许可证均公开。关于 Codex 的官方项目概念可参考 [Projects and chats](https://learn.chatgpt.com/docs/projects)；这里的配置适配依据是本地观察，不代表官方承诺的稳定接口。
